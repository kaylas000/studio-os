# STUDIO OS v2.1.0

> **Мета-система веб-студии нового поколения, живая библиотека производственных модулей и интерактивный портал-шоукейс.**

---

## 🌟 Концепция STUDIO OS

**STUDIO OS** — это саморазвивающаяся производственная операционная система веб-студии, объединяющая:

1. **Производственный конвейер (Production Core & CLI)**:
   - Создание клиентских проектов в `/projects/` с принудительной инъекцией всех 9 систем студии.
   - Механизм **Harvesting** (`studio harvest`): автоматическое извлечение и деперсонализация удачных блоков для обогащения центральной библиотеки `/library/`.
   - Хранилище ассетов `/library/assets-vault/` с автоматической Draco-компрессией 3D-моделей, конвертацией звуков и шрифтов.

2. **Интерактивный сайт-шоукейс (Living Showcase Portal)**:
   - Построен на базе этих же систем (*Dogfooding*).
   - Каждый блок сайта — интерактивный демонстрационный стенд системы (3D WebGL заставки, скраббинг анимаций, анти-слоп сканер, 5 дизайн-архетипов, радар отступов, мобильная лаборатория, SEO-краулер, анализатор фактуры текста и Zero-Bug монитор).
   - Модальные окна скачивания ZIP-архивов систем, калькулятор заказа сайта и Drag-and-Drop загрузчик файлов с ПК прямо в папки библиотеки.

## 🚀 Быстрый Старт

### 1. Поставить зависимости и запустить витрину:
```bash
npm install
npm run dev                                        # сайт-витрина студии, http://localhost:3000
npm run dev --workspace=projects/client-vylet        # клиентский проект (спецтехника, Cyber-Tech)
```

### 2. Создание нового клиентского проекта:
```bash
npx studio new client-aurum luxury-noir
# Разворачивает проект в projects/client-aurum со всеми 9 подключенными системами
```

### 3. Сбор удачного блока в библиотеку (Harvesting):
```bash
npx studio harvest cyber-hero components
# Сохраняет очищенный компонент в /library/components/
```

### 4. Прогон полного аудита качества:
```bash
npx studio audit                     # все проекты в projects/ + сводка по студии
npx studio audit projects/client-vylet --quiet
npx studio audit showcase-site --loose
npm run verify                       # 27 тестов: APCA, клише, спейсинг, Zero-Bug, парсер, E2E-аудит
npm run smoke                        # сборка клиента + монтирование в jsdom (15 проверок)
```

### 5. Прочие команды ядра:
```bash
npx studio tokens cyber-tech projects/client-vylet   # перегенерить src/styles/archetype.css из TokenEngine
npx studio archetypes                                 # APCA-статус всех 5 архетипов
npx studio vault                                      # инвентарь ассетов с чтением заголовков форматов
npx studio harvest client-vylet 02-FleetTable sections # деперсонализация и перенос блока в library/
```

## 🔧 Что изменилось в v2.1.0

- **Аудит стал настоящим.** `studio audit` читает исходники проекта и вызывает детекторы из `library/`:
  клише, слоп-градиенты (ΔE CIE76 + структурные признаки), off-scale отступы, 19 вьюпортов,
  APCA-контраст архетипа и брендовой палитры, факт-плотность, читаемость, PAS, layout thrashing,
  `dispose()` WebGL и SEO-контракт (реальный импорт `src/content/seo.ts`). Результат —
  `studio.audit.json` в проекте, блокирующие нарушения подсчитываются отдельно от предупреждений.
- **`` и `\w` не знают кириллицы.** Вся regex-слой библиотеки переведён на `\p{L}` + флаг `u`:
  до этого «350 000 руб» и «14 дней» не матчились вовсе, а факт-плотность врала в обе стороны.
- **APCA реализована по-настоящему** (`library/07-archetypes/contrast.ts`) с калибровкой по якорям
  106 / −108 / 62.7 Lc, и все 5 архетипов прошли собственный контраст-гейт (раньше падали 4 из 5).
- **Шрифты архетипов** заменены на кириллица-совместимые: в стеках были Orbitron / Share Tech Mono /
  Cinzel, у которых нет кириллицы — RU-текст уезжал в системный sans.
- **`IntroEngine` больше не роняет страницу** при недоступном WebGL и корректно освобождает контекст;
  `MotionGuard` (новый) — единый гейт движения: reduced-motion, Data Saver, батарея, слабый GPU.
- **`studio harvest` и `studio vault` работают с файлами**: переписывание импортов на алиасы,
  вырезание контактов и ИНН, sha256-подпись манифеста; чтение заголовков PNG/JPEG/WebP/GLB(Draco)/WOFF2.
- **Два новых гейта в SYS-09/SYS-06**: каждый файл проекта прогоняется через `esbuild` (непарсящийся
  исходник больше не получает «100/100»), а SEO-контракт с текстом из каркаса (`заполните title`, `TODO`)
  блокирует релиз — `studio new`-проект принципиально не может пройти аудит до заполнения данных.
- **Гейт стал строже, а не мягче.** Аудит читает `.js/.jsx` наравне с `.ts/.tsx` (копирайт регулярно
  лежит в `src/data/*.js` и проходил мимо проверки), проза вытаскивается построчно — апостроф в JSX-тексте
  больше не «съедает» соседние строки, — а `esbuild`-парсинг в SYS-09 не даёт поставить 100/100 файлу,
  который не собирается. `SYS-06` блокирует релиз, пока в `seo.config.ts` живут строки из каркаса.
- **Метрики пересчитаны честно.** SpacingTokenGuard считает долю токенов по слотам (shorthand
  `padding: var(--a) var(--b)` больше не даёт «лишние» пиксели), ReadabilityAnalyzer видит перенос строки
  как границу смыслового блока, FactDensityScorer игнорирует ИНН, телефоны, координаты и номера версий,
  но засчитывает деньги, температуры и длительности. Номера строк в отчёте — реальные строки файла.
- **Показательный провал**: `npx studio audit showcase-site` — Originality 64/100, 146 off-scale
  отступов и слоп-тексты. Витрина демонстрирует системы, но сама стандартам ещё не соответствует.

## 📤 Заливка на GitHub

Чтобы запушить STUDIO OS в ваш репозиторий на GitHub:

```bash
# 1. Добавьте ваш удаленный репозиторий GitHub
git remote add origin https://github.com/ВАШ_АККАУНТ/studio-os.git

# 2. Переименуйте ветку в main
git branch -M main

# 3. Отправьте код в репозиторий
git push -u origin main
```
